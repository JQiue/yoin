# 快速开始

这一页把 Yoin 跑起来，并准备好第一个站点。全程只需要一个进程和一个数据库。

## 需要什么

- 一台能跑 Rust 服务的机器
- 从源码构建时才需要 Node.js + npm（前端产物在编译期打进二进制）

## 启动服务

```bash
cargo run
```

首次启动会自动建库、执行迁移、创建默认站点，不需要手动初始化数据库。

服务接受四个部署参数（可用 `.env` 文件或环境变量提供）：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite://./yoin.sqlite?mode=rwc` | 数据库连接串，默认在当前目录建一个 SQLite 文件 |
| `HOST` | `127.0.0.1` | 监听地址 |
| `PORT` | `7410` | 监听端口 |
| `JWT_KEY` | 随机生成 | 签发登录令牌的密钥，**至少 32 个字符** |

`JWT_KEY` 不设置时每次重启都会换一把临时密钥，所有人都要重新登录——正式部署请固定下来。

启动后可以确认服务活着：

```bash
curl http://127.0.0.1:7410/api/health
```

## 打开管理后台

管理后台和评论组件一样，是一个需要挂到页面上的前端应用。新建一个 HTML 文件（或塞进你现有站点的某个页面）：

```html
<div id="yoin-admin"></div>

<script src="https://你的域名/static/admin.js"></script>
<script>
  new YoinAdmin({ containerId: "yoin-admin" });
</script>
```

打开这个页面，用邮箱注册。**第一个注册的账号自动成为超级管理员**，同时系统会为它创建一个默认站点。

## 拿到站点 id

管理后台的「站点」页列出了站点及其编号。评论组件按**站点**区分：同一个站点共享配置、权限和评论数据。嵌入时要用这个编号（通常是 `1`）。
