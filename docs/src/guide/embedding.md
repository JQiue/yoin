# 嵌入到你的网站

评论组件是一个独立脚本，把它引到页面里、给一个容器，就完事了。

```html
<div id="yoin-comments"></div>

<script src="https://你的域名/static/client.js"></script>
<script>
  new YoinClient({
    containerId: "yoin-comments",
    site_id: 1,
    api_base: "https://你的域名",
  });
</script>
```

## 要填的东西

| 选项 | 填什么 |
| --- | --- |
| `containerId` | 你自己写的容器元素 id（找不到时组件只在控制台报错，不影响页面其他部分） |
| `site_id` | 站点编号，见管理后台的「站点」页 |
| `api_base` | Yoin 服务的地址；如果评论服务和你网站**同域**就留空，跨域时写完整地址（结尾不要加斜杠） |

## 评论挂在哪一页

组件按**当前页面的地址**归类评论：同一个 URL 的访客看到同一串评论，不同文章互不干扰，你不需要额外传参数。

两个随之而来的注意点：

- 文章**换 URL（改名、换目录）之后，旧评论不会跟过去**——这是按地址归类的必然结果；
- 如果你有那种「整本/整站合一」的长页面（例如文档站导出的打印页），把它排除掉，否则整站会共用一条评论线程。

## 主题与语言

- **深色模式跟随你的网站**：站点在 `<html>` 上用 `class` 或 `data-theme` 声明主题时以站点为准（mdBook 的 `light`/`rust` 是浅色，`coal`/`navy`/`ayu` 是暗色），读者切换主题时评论组件**实时跟随、不用刷新**；站点没声明主题时跟随读者操作系统的配色；
- **界面语言跟随页面的 `lang` 属性**：`<html lang="zh">` 显示中文，其余显示英文；
- 组件的样式都限定在自己的容器里，不会影响你页面的其他部分。

## 跨域部署

评论服务可以直接挂在任意域名下，不需要和 Yoin 同域：

- 组件用非凭据方式发起请求，服务端默认的宽松 CORS 策略即可放行，你**不需要**在服务端做额外配置；
- 游客身份走请求头和浏览器本地存储，不依赖 cookie；
- 如果你的站点是 https，Yoin 也必须是 https（否则浏览器会拦截混合内容）。

想把登录态、游客 cookie 也一并复用，最省事的是**同域部署**：把 `/api` 反向代理到 Yoin，`api_base` 留空即可。

## 组件的其他能力

- 访客用第三方登录（GitHub / QQ）后会以该身份发言，需要先在后台[配置第三方登录](oauth-login.md)；
- 登录用户能看到自己的私密评论，站点管理员能看到该站点的全部评论（含私密）；
- 组件实例带 `destroy()`，用于在单页应用里卸载。

需要精确的选项定义、评论归属规则、样式作用域等实现细节，见开发者指南的[组件接口与嵌入细节](../dev/widget.md)。
