# 成员与权限

## 内置角色

系统自带三种角色，按住它们能做的事划分：

| 角色 | 能做什么 |
| --- | --- |
| 超级管理员 | 全部：管理站点、审核评论、删除任意评论、管理第三方登录、管理审核提供商 |
| 站点管理员 | 管理站点（含站点设置与置顶）、管理第三方登录、管理审核提供商 |
| 审核员 | 审核评论（改状态）、删除任意评论 |

后台里没有「超级管理员之外的人改角色」这一说的例外——**最后一个超级管理员不能被降级**，避免把自己锁在门外。

## 绑定与作用域

授权有两种作用域：

- **全局**：对全部站点生效，通常只给超级管理员；
- **指定站点**：只对该站点生效，例如让某个审核员只负责某个站点。

一个账号可以有多个绑定。判断「能不能做某事」时，系统会同时看全局权限和该站点的站点级权限。

## 第一个账号

第一个注册的账号（无论邮箱注册还是第三方登录）自动成为全局超级管理员，并获得一个默认站点。之后注册的账号都是普通用户，需要由管理员在后台授权。

## 在后台操作

后台 → 「权限」页：

- 「System roles」列出各角色当前拥有的权限，可直接勾选调整（保存即生效）；
- 「User role bindings」把某个账号绑定到某个角色，并选择作用域（全局或某个站点）；
- 「My permission snapshot」显示你自己当前的权限，用来确认授权是否符合预期。

## 需要精确取值时

权限码字符串、角色与权限的完整对应关系、以及相关接口，见开发者指南的[权限模型](../dev/rbac.md)。
